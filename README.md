# MedGuard AI

MedGuard AI is an early-stage project for evidence-grounded medication safety research and drug interaction analysis. The repository currently contains a small FastAPI backend foundation and a collection of standalone scripts for exploring and auditing openFDA drug-label data.

> **Current scope:** the API does not yet identify medications, retrieve or verify evidence, or analyze interactions. It only reports basic service information and health. The datawork scripts are exploratory and do not produce clinically validated conclusions.

## What is implemented

### FastAPI service

The application is defined in `app/main.py` and currently exposes:

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/` | Returns the service name, version, and running status. |
| `GET` | `/health` | Returns a basic process health response. |
| `GET` | `/docs` | Interactive Swagger UI generated by FastAPI. |
| `GET` | `/openapi.json` | Generated OpenAPI schema. |

### Data exploration scripts

The scripts in `app/services/datawork/` are for inspecting openFDA Structured Product Label (SPL) JSON exports and candidate interaction text. They use simple field checks and limited text patterns; they are not a drug terminology resolver or an interaction knowledge base.

| Script | What it does |
| --- | --- |
| `audit_labels.py` | Counts records and the presence of selected label sections in each source file. |
| `audit_interactions.py` | Reports record ID duplication/missingness and counts records with interaction text; prints a few examples. |
| `audit_evidence_quality.py` | Summarizes interaction-text availability, identity metadata coverage, and text lengths. |
| `check_interaction_text.py` | Checks interaction passages for empty text and missing product identity and prints examples. |
| `inspect_missing_identity.py` | Looks at interaction passages whose product records lack the identity fields checked by the script, with a few keyword-pattern examples. |
| `extract_evidence.py` | Streams selected label fields into `drug_label_evidence.jsonl`, deduplicating records by label ID. |
| `extract_interaction_candidates.py` | Writes interaction passages and available product metadata to `interaction_candidates.jsonl`; adds matches from a small, explicitly unreviewed list of class terms. |
| `audit_interaction_candidates.py` | Reads the adjacent `interaction_candidates.jsonl` and writes `interaction_audit_report.json`, including identity and text coverage counts. |
| `inspect_unidentified_candidates.py` | Inspects records without structured identity and prints selected named-drug or drug-class pattern matches. |

`unidentified_candidates_sample.csv` is a small working sample of candidate passages. The large source exports and generated JSON/JSONL files are not part of the tracked project files; `.gitignore` excludes local `*.json` and `*.jsonl` files under `app/services/datawork/`.

## Planned, but not implemented

The project goals include:

- Medication name normalization using RxNorm.
- Retrieval of medication safety evidence from reliable sources.
- Analysis of potential drug interactions.
- A medication knowledge graph using Neo4j.
- GraphRAG retrieval and a LangGraph workflow.
- Evidence verification before generating user-facing reports.

There are no current API routes or application modules implementing these capabilities. In particular, there is no medication-analysis endpoint, database connection, graph, retrieval pipeline, or LLM workflow in this repository yet.

## Requirements and setup

- Python 3.12 or compatible with the version declared in `pyproject.toml`.
- Git.

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
```

The project dependencies are FastAPI, Uvicorn, HTTPX, and Pydantic Settings. Development dependencies add pytest and Ruff. `uv.lock` records a locked environment for the Docker build.

> The standalone datawork scripts import `ijson`, but `ijson` is not currently declared in `pyproject.toml`. Add/install that dependency in the environment before running those scripts. Their input files are expected to be named `drug-label-*.json` and, for most scripts, to be in the current working directory.

## Run the API locally

From the repository root, after activating the virtual environment:

```powershell
uvicorn app.main:app --reload
```

Open the generated docs at `http://127.0.0.1:8000/docs`, or check `http://127.0.0.1:8000/health`.

## Run with Docker Compose

Docker and Docker Compose are required. From the repository root:

```powershell
docker compose up --build
```

Compose publishes the API on port `8000` and mounts `app/` and `tests/` into the container for development. The example environment values are `APP_NAME`, `APP_ENV`, and `LOG_LEVEL`. They are present in `.env.example` and Compose, but the current `app/main.py` does not yet load or use them.

## Tests and code quality

The existing tests in `tests/test_health.py` cover the root response, health response, and OpenAPI availability. To run the checks:

```powershell
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
```

## Running the datawork scripts

These scripts are independent analysis utilities, not part of the API request path. After installing `ijson` and placing the source export files (`drug-label-*.json`) in the expected working directory, run a script from the repository root, for example:

```powershell
python app/services/datawork/audit_labels.py
```

The two extractors write their JSONL outputs to the current working directory. `audit_interaction_candidates.py` instead looks for `interaction_candidates.jsonl` beside the script and writes its report beside it. Check each script's `OUTPUT`, `INPUT_FILE`, and `REPORT_FILE` constants before running it so input and output paths are clear.

## Safety and data limitations

- This repository is infrastructure and data exploration only. It does not provide medication recommendations, diagnosis, or clinical conclusions.
- openFDA label content and extracted candidates require validation. Text pattern matches indicate possible passages to review, not confirmed drug interactions.
- The current scripts use limited identity fields and hard-coded example terms. They do not reliably normalize brand names, ingredients, salts, or drug classes.
- Do not use the current API or datawork outputs to make patient-care decisions.
